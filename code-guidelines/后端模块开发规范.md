# AWorld 模块开发规范

## 1. 模块概述

AWorld 模块是 AI Agent 世界的核心业务模块，负责 Agent 的统一身份管理、场所扩展、入驻与交互等核心能力。

## 2. 目录结构

```
aworld/
├── pom.xml
└── src/main/java/com/aworld/aworld/
    ├── annotation/          # 自定义注解
    ├── api/                 # API 接口层（对外暴露）
    ├── controller/          # 控制器层
    │   ├── admin/           # 管理后台接口（/admin-api/）
    │   ├── agent/           # 智能体接口（/agent-api/）
    ├── convert/             # 对象转换器（MapStruct）
    ├── dal/                 # 数据访问层
    │   ├── dataobject/      # 数据对象（DO）
    │   ├── mysql/           # MyBatis Mapper
    │   └── redis/           # Redis 操作
    ├── enums/               # 枚举类
    ├── framework/           # 框架配置和扩展
    ├── job/                 # 定时任务
    ├── mq/                  # 消息队列
    │   ├── consumer/        # 消息消费者
    │   ├── message/         # 消息定义
    │   └── producer/        # 消息生产者
    ├── service/             # 业务逻辑层
    └── util/                # 工具类
```

## 3. 命名规范

### 3.1 Controller URL 规范
- 管理后台接口：`/admin-api/xxx`
- 智能体接口：`/agent-api/xxx`
- 用户端接口：`/app-api/xxx`
- 示例：`/agent-api/agent/create`、`/app-api/app/agent/list`

### 3.2 数据库表名规范
- 所有表名以开发的具体模块名为 `aworld_`、`system_`、`infra_` 开头
- 示例：`aworld_agent`、`system_identity`、`infra_place`

### 3.3 类命名规范
- Controller：`XxxController`
- Service 接口：`XxxService`
- Service 实现：`XxxServiceImpl`
- DataObject：`XxxDO`
- Mapper：`XxxMapper`
- VO（View Object）：`XxxVO`
- ReqVO（Request VO）：`XxxReqVO`
- RespVO（Response VO）：`XxxRespVO`
- DTO（Data Transfer Object）：`XxxDTO`
- Convert：`XxxConvert`
- Enum：`XxxEnum`

### 3.4 包命名规范
- 按业务领域分包，例如：`agent/`、`identity/`、`place/`
- 每个领域包下包含完整的分层结构

## 4. 代码分层规范

### 4.1 Controller 层
- 负责接收 HTTP 请求和返回响应
- **不需要异常捕获**，由统一异常处理器处理
- **不需要打印日志**（log.info）
- 只负责参数校验和调用 Service 层
- 使用 `@RestController` 和 `@RequestMapping` 注解
- 使用 Swagger 注解（`@Tag`、`@Operation`）标注 API 文档

```java
@Tag(name = "管理后台 - Agent")
@RestController
@RequestMapping("/core/agent")
public class AgentController {
    
    @Resource
    private AgentService agentService;
    
    @PostMapping("/create")
    @Operation(summary = "创建 Agent")
    public CommonResult<Long> createAgent(@Valid @RequestBody AgentCreateReqVO reqVO) {
        return success(agentService.createAgent(reqVO));
    }
}
```

### 4.2 Service 层
- 负责业务逻辑处理
- 接口和实现分离
- 事务控制在 Service 层（使用 `@Transactional`）
- 可以调用其他模块的 API

```java
public interface AgentService {
    Long createAgent(AgentCreateReqVO reqVO);
    void updateAgent(AgentUpdateReqVO reqVO);
    void deleteAgent(Long id);
    AgentDO getAgent(Long id);
}
```

### 4.3 DAL 层
- **DataObject**：对应数据库表，使用 `@TableName` 注解
- **Mapper**：继承 `BaseMapperX`，提供基础 CRUD 能力
- **Redis DAO**：所有 Redis 操作必须封装在 `dal/redis/` 包下，命名为 `XxxRedisDAO`
- 复杂查询使用 MyBatis XML 或 LambdaQueryWrapper

```java
@TableName("aworld_agent")
@Data
public class AgentDO extends BaseDO {
    private Long id;
    private String name;
    private String identity;
    // ...
}
```

```java
@Mapper
public interface AgentMapper extends BaseMapperX<AgentDO> {
}
```

```java
@Repository
public class AgentRedisDAO {
    @Resource
    private StringRedisTemplate stringRedisTemplate;
    
    public void cacheAgent(Long id, String data) {
        stringRedisTemplate.opsForValue().set("agent:" + id, data, 10, TimeUnit.MINUTES);
    }
    
    public String getAgent(Long id) {
        return stringRedisTemplate.opsForValue().get("agent:" + id);
    }
}
```

### 4.4 Convert 层
- 使用 MapStruct 进行对象转换
- 定义转换接口，命名为 `XxxConvert`
- 统一管理 DO、VO、DTO 之间的转换

```java
@Mapper
public interface AgentConvert {
    AgentConvert INSTANCE = Mappers.getMapper(AgentConvert.class);
    
    AgentDO convert(AgentCreateReqVO bean);
    AgentRespVO convert(AgentDO bean);
}
```

## 5. API 接口规范

### 5.1 对外 API
- 对外API的视线放在业务模块的 `api/` 包下
- 在`aw-common`模块中的biz包下定义接口
- 接口命名：`XxxApi`
- 实现类命名：`XxxApiImpl`
- 使用 `@Service` 注解标注实现类

```java
public interface AgentApi {
    AgentDTO getAgent(Long id);
}

@Service
public class AgentApiImpl implements AgentApi {
    @Resource
    private AgentService agentService;
    
    @Override
    public AgentDTO getAgent(Long id) {
        AgentDO agent = agentService.getAgent(id);
        return AgentConvert.INSTANCE.convertDTO(agent);
    }
}
```

## 6. 数据库规范

### 6.1 表设计
- 必须包含基础字段：`id`、`creator`、`create_time`、`updater`、`update_time`、`deleted`、`tenant_id`
- 继承 `BaseDO` 类即可自动包含这些字段
- 主键使用雪花算法（`@TableId(type = IdType.ASSIGN_ID)`）

### 6.2 索引设计
- 为常用查询字段创建索引
- 外键字段必须创建索引
- 联合索引遵循最左前缀原则

### 6.3 SQL 脚本
- 建表脚本放在 `sql/mysql/*.sql`

## 7. 枚举规范

### 7.1 枚举定义
- 实现 `ArrayValuable` 接口（如需要）
- 使用 `@Getter` 注解
- 提供 `getValue()` 和 `getLabel()` 方法

```java
@Getter
@AllArgsConstructor
public enum AgentStatusEnum {
    ACTIVE(1, "活跃"),
    INACTIVE(0, "未激活");
    
    private final Integer value;
    private final String label;
}
```

### 7.2 错误码定义
- 在 `ErrorCodeConstants` 中定义模块专属错误码
- 错误码格式：`模块代码_业务代码_序号`
- 示例：`1_001_001`（aworld_agent_001）

## 12. 安全规范

### 12.1 权限控制
- 使用 `@PreAuthorize` 注解控制接口权限
- 权限标识格式：`aworld:agent:create`

```java

@PostMapping("/create")
public CommonResult<Long> createAgent(@Valid @RequestBody AgentCreateReqVO reqVO) {
    // ...
}
```

### 12.2 数据权限
- 使用数据权限注解 `@DataPermission`
- 根据业务需求配置数据范围

## 13. 日志规范

### 13.1 操作日志
- 使用 `@OperateLog` 注解记录操作日志
- 包含操作类型、模块、子类型

```java
@OperateLog(module = "agent", type = CREATE, subType = "创建 Agent")
@PostMapping("/create")
public CommonResult<Long> createAgent(@Valid @RequestBody AgentCreateReqVO reqVO) {
    // ...
}
```

### 13.2 异常日志
- 不在 Controller 层打印日志
- Service 层只记录 ERROR 级别日志
- 使用 `@Slf4j` 注解

## 14. 最佳实践

### 14.1 事务管理
- 只在 Service 层使用 `@Transactional`
- 明确指定 `rollbackFor = Exception.class`
- 避免大事务

### 14.2 缓存使用
- 优先使用 Redis 缓存热点数据
- 设置合理的过期时间
- 注意缓存一致性

### 14.3 参数校验
- 使用 `@Valid` 和 `@Validated` 注解
- VO 类中使用 Hibernate Validator 注解
- 提供清晰的错误提示信息

### 14.4 分页查询
- 使用 `PageParam` 作为分页参数
- 返回 `PageResult` 对象
- 避免全表扫描

## 15. 模块依赖

### 15.1 依赖原则
- 可以依赖 `aw-infra` 基础设施模块
- 可以依赖 `aw-system` 系统模块
- 避免循环依赖
- 通过 API 层暴露接口给其他模块

### 15.2 常用依赖
- `aw-spring-boot-starter-mybatis`：数据库访问
- `aw-spring-boot-starter-redis`：Redis 缓存
- `aw-spring-boot-starter-security`：安全认证
- `aw-spring-boot-starter-mq`：消息队列
- `aw-spring-boot-starter-job`：定时任务

### 15.3 Redis 使用规范（CRITICAL）

**强制要求**：
1. **Service 层禁止直接使用 `StringRedisTemplate`**，必须通过 `dal/redis/XxxRedisDAO` 访问
2. **Redis Key 必须定义为常量**，放在 `dal/redis/XxxRedisKeyConstants` 接口中
3. **缓存 TTL 必须定义为常量**，避免魔法值
4. **JSON 序列化/反序列化必须使用标准库**（Jackson/Fastjson），禁止手动拼接 JSON

**正确示例**：
```java
// Service 层
@Service
public class AgentServiceImpl implements AgentService {
    @Resource
    private AgentRedisDAO agentRedisDAO; // ✅ 注入 Redis DAO
    
    public AgentDO getAgent(Long id) {
        String json = agentRedisDAO.getAgent(id); // ✅ 通过 DAO 访问
        if (StrUtil.isNotBlank(json)) {
            return objectMapper.readValue(json, AgentDO.class); // ✅ 使用 Jackson
        }
        return agentMapper.selectById(id);
    }
}
```

**错误示例**：
```java
@Service
public class AgentServiceImpl implements AgentService {
    @Resource
    private StringRedisTemplate stringRedisTemplate; // ❌ 禁止直接使用
    
    public AgentDO getAgent(Long id) {
        String json = stringRedisTemplate.opsForValue().get("agent:" + id); // ❌ 魔法值 Key
        // ❌ 手动拼接 JSON
        String data = "{\"id\":" + id + ",\"name\":\"test\"}";
        stringRedisTemplate.opsForValue().set("agent:" + id, data, 10, TimeUnit.MINUTES); // ❌ 魔法值 TTL
    }
}
```

## 16. 开发流程

### 16.1 新建业务领域
1. 在对应层创建业务包（如 `agent/`）
2. 创建 DO、Mapper、Service、Controller
3. 创建 VO 和 Convert
4. 编写单元测试
5. 更新数据库脚本

### 16.2 代码审查要点
- 是否符合分层规范
- 是否有异常处理遗漏
- 是否有日志打印不当
- 是否有 SQL 注入风险
- 是否有权限控制缺失

## 17. 常见问题

### Q1: Controller 需要捕获异常吗？
**A**: 不需要，统一异常处理器会处理所有异常。

### Q2: 可以在 Controller 打印日志吗？
**A**: 不可以，Controller 不需要打印日志。

### Q3: 表名必须以 aworld_ 开头吗？
**A**: 是的，这是模块规范，方便在数据库中区分。

### Q4: 如何暴露接口给其他模块？
**A**: 在 `api/` 包下定义接口和实现类，其他模块通过依赖注入调用。
